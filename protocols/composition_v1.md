UFCPS Composition Protocol v1

1. Purpose

This protocol defines how multiple procedural states, branches, results, or partial resolutions are composed into a subsequent procedural unit.

Composition is a controlled operation of integration.

It is not simple concatenation of outputs.

The purpose of composition is to create a successor state that preserves the distinctions required to continue the process while integrating compatible contributions.

2. Core Principle

The canonical relation is:

P_n+1a + P_n+1b -> P_n+2

The two contributing procedural units may contain:

compatible results

complementary partial results

independent observations

unresolved contradictions

alternative hypotheses

different representations of the same structural difference

Composition must preserve the provenance and logical status of each contribution.

3. Composition Preconditions

Composition is valid only when:

The contributing states are identifiable.

Their provenance is preserved.

Their continuation-relevant state can be accessed.

The relation between the contributions is explicit.

The resulting state can represent any remaining difference.

The composition operation itself is recorded.

A system must not silently merge states whose semantic relation is unknown.

4. Composition Inputs

A composition may receive one or more of:

procedural states

local results

delegated results

experimental results

parallel branch states

partial derivations

observations

constraints

alternative strategies

validated external inputs

Every input should have a unique reference.

5. Provenance

Each contribution must retain its origin.

Minimum provenance information includes:

source procedural unit

source carrier

source branch, when applicable

source operation

result status

validation status

Provenance prevents an integrated result from being mistaken for an original observation or a single-agent conclusion.

6. Compatible Composition

Compatible states may be composed when their continuation-relevant information does not conflict.

Examples include:

independent measurements supporting the same state

partial solutions addressing different parts of a task

complementary derivations

separate observations constraining the same hypothesis

A compatible composition produces a new procedural state containing the integrated result.

The original states remain identifiable as contributors.

7. Complementary Composition

Two states may be complementary without being individually sufficient.

For example:

State_A -> resolves Difference_A

and

State_B -> resolves Difference_B

where both differences are components of a larger structural difference.

The composition may therefore produce:

Difference_A + Difference_B -> Difference_AB

The successor procedural unit should explicitly record how the components were combined.

8. Contradictory Composition

Contradictory states must not be silently reconciled.

For example:

Result_A = X

and

Result_B = not X

is a valid input to composition.

The resulting state should preserve:

both results

their provenance

the conditions under which each arose

the contradiction itself

the unresolved difference generated by the contradiction

A contradiction may become the primary input for the next procedural unit.

9. Composition as Difference Generation

Composition may itself generate a new structural difference.

Therefore the operation is not merely:

A + B -> C

but may be:

A + B -> Difference_C -> P_n+2

The newly generated difference may concern:

incompatibility

missing information

scale mismatch

boundary conditions

causal assumptions

representation mismatch

experimental discrepancy

The generated difference must remain explicit.

10. Fix Before Composition

Continuation-relevant distinctions should be preserved before composition.

The canonical sequence is:

diff -> fix -> diss -> unfold

For composition, this implies:

identify the relevant differences

preserve them as explicit state

release state from exclusive dependence on the original carriers

construct the successor state

Composition should therefore operate on preserved procedural state rather than on transient agent memory alone.

11. Dissipation in Composition

In UFCPS, dissipation does not mean deletion.

Dissipation means release of preserved state from exclusive dependence on a particular carrier.

Before composition:

Carrier_A -> State_A

and

Carrier_B -> State_B

After dissipation:

State_A
and
State_B

remain available as process state independent of the continued activity of either carrier.

The system may then compose them.

12. Composition and Delegation

Delegation may precede composition.

For example:

P_n -> P_n+1a
P_n -> P_n+1b

The resulting branch states may later be transferred to a composition-capable carrier.

Delegation changes the carrier.

Composition changes the procedural organization of the preserved states.

These are distinct operations.

13. Composition and Branching

Branching creates alternatives.

Composition integrates contributions from one or more branches.

Therefore:

Branching != Composition

A branch may remain independent.

Composition occurs only when the system explicitly determines that integration is useful or required.

14. Composition Record

Every composition should record:

composition identifier

input state references

input procedural unit references

provenance

composition relation

compatibility status

resulting difference

resulting state

unresolved differences

next required operation

validation status

The record must be sufficient for later reconstruction of how the successor state was obtained.

15. Composition Relations

The protocol recognizes the following relations:

15.1 Merge

Two states can be combined without unresolved conflict.

A + B -> C

15.2 Complement

One state provides information missing from another.

A + B -> Complete_AB

15.3 Constraint

One state limits the admissible interpretation of another.

A + Constraint_B -> Restricted_A

15.4 Corroboration

Independent states support a compatible result.

A + B -> Supported_Result

15.5 Contradiction

Two states cannot currently be reconciled.

A + B -> Unresolved_Difference

15.6 Transformation

A representation in one state provides a basis for constructing another representation.

Representation_A -> Representation_B

15.7 Synthesis

Several compatible states form a higher-level procedural state.

A + B + C -> Synthesized_State

The selected relation must be explicit.

16. Validation

Composition validation occurs at several levels.

Structural validation

Checks that:

required input states exist

references are valid

provenance is present

output state is well formed

Procedural validation

Checks that:

the composition operation is permitted

input states are compatible with the selected relation

unresolved differences are preserved

successor state is correctly formed

Runtime validation

Checks properties that require execution context, such as:

task-specific correctness

empirical validity

reproducibility

convergence

downstream utility

Schema validation alone does not establish these properties.

17. No Silent Normalization

The composition layer must not silently:

delete conflicting evidence

choose one contradictory branch

convert uncertainty into certainty

convert partial results into complete results

erase failed approaches

replace provenance with a summary

infer agreement where none was established

Any normalization must be an explicit operation with a recorded rationale.

18. Uncertainty Preservation

If an input state contains uncertainty, the composition must preserve it unless the composition itself provides a valid basis for reducing that uncertainty.

For example:

Uncertainty_A + Uncertainty_B

does not automatically become:

Certainty_C

The resulting uncertainty status must reflect the actual information available.

19. Negative and Anomalous Results

Negative results remain valid composition inputs.

Examples:

hypothesis disconfirmed

expected observation absent

experiment invalid

result unreproducible

anomaly detected

search path exhausted

Such states may constrain future continuation.

Therefore:

Failed Path -> Information

and:

Anomaly -> Difference

Composition must preserve these states rather than discard them as useless outputs.

20. Composition with Experimental Results

Experimental states may be composed with:

theoretical states

simulation results

independent experiments

observational data

prior hypotheses

model constraints

The composition must distinguish:

observation

interpretation

hypothesis

derived claim

No composition operation should transform an interpretation into an observation merely by merging records.

21. Composition of Partial Solutions

A partial solution may be composed with another partial solution when their scopes are compatible.

Each partial solution must retain:

solved region or component

unresolved region or component

assumptions

constraints

dependencies

The composed state is complete only when the required scope has been covered and validated.

Otherwise it remains partial.

22. Composition Failure

Composition may fail.

Possible reasons include:

incompatible state representations

contradictory constraints

missing provenance

insufficient information

invalid references

incompatible assumptions

unresolved semantic mismatch

Composition failure is itself a valid procedural result.

It may produce:

Composition Failure -> New Difference -> Next Procedural Unit

It does not automatically terminate the process.

23. Recursive Composition

Composition may be applied to outputs that were themselves composed.

This creates hierarchical procedural structures.

C5 recursion control applies.

A runtime must define:

current composition depth

maximum permitted depth

action on overflow

Possible overflow actions include:

delegate

branch

pause

terminate

24. Swarm Composition

In a swarm, composition may occur across carriers.

For example:

Carrier_A -> P_n+1a
Carrier_B -> P_n+1b
Carrier_C -> P_n+1c

followed by:

P_n+1a + P_n+1b + P_n+1c -> P_n+2

The composition carrier may be:

one of the original carriers

a dedicated synthesis agent

a specialized validator

another compatible carrier

Carrier identity is not part of the semantic identity of the composed process state.

25. Composition and Continuity

Composition contributes to process continuity when its resulting state is a valid successor state.

The essential relation is:

Preserved Inputs -> Composition -> Successor State

The successor may:

resolve the current difference

generate a new difference

create branches

request delegation

begin an experiment

terminate under a valid global condition

26. Composition and the Present Procedural Unit

A composed state is itself a complete procedural state for the next step.

It should not be treated as a permanent object.

The state is valid as:

P_n

only for the duration of its current procedural role.

Once it generates the next difference and transition:

P_n -> P_n+1

the previous procedural unit becomes part of process history.

27. Canonical Composition Sequence

The canonical composition sequence is:

collect -> preserve -> compare -> relate -> compose -> validate -> unfold

Where:

collect identifies candidate inputs

preserve retains continuation-relevant state

compare identifies differences and common structure

relate determines the composition relation

compose constructs the integrated state

validate checks the composition

unfold instantiates the next procedural state

This sequence specializes the general UFCPS operator flow:

diff -> fix -> diss -> unfold

28. Composition Invariant

The composition invariant is:

A composition operation may integrate procedural states, but it must preserve provenance, relevant differences, uncertainty, and unresolved contradictions required for valid continuation.

29. Relation to UFCPS

This protocol provides the composition layer between:

parallel procedural execution

state preservation

branch management

result integration

contradiction handling

successor-state construction

It complements:

SCP v1 for step continuity

swarm continuity v1 for carrier-independent process continuity

experimental autonomy v1 for autonomous research

procedural state v1 for common state representation

30. Status

Version: v1

Status: conceptual protocol specification

Executable enforcement requires compatible state schemas, composition records, runtime validators, and evaluation procedures.
